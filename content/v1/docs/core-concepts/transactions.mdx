---
title: Transactions
description: Atomic operations with automatic rollback
---

Transactions group multiple database operations into one atomic unit. If the
callback throws, the adapter rolls back its writes.

## Basic usage

```ts
const result = await db.transaction(async (ctx) => {
  const todos = ctx.collection("todos")
  await todos.create({ title: "Write docs" })
  await todos.create({ title: "Ship v2" })
  return "done"
})
```

Both creates succeed together, or neither is committed. Transactional writes
run validation and before-hooks in the transaction; after-hooks and change
events run only after commit. Aborted writes emit no post-commit events.

## TransactionContext API

Inside a transaction callback, use the transaction-scoped collection returned
by `ctx.collection(name){:ts}`. Do not use `db.collection()` for work that must
participate in the transaction.

| Method | Signature | Description |
|---|---|---|
| `findAll{:ts}` | `() => Promise<T[]>{:ts}` | All records in the collection |
| `findById{:ts}` | `(id: ID) => Promise<T \| undefined>{:ts}` | Single record by ID |
| `create{:ts}` | `(data: Partial<T>) => Promise<T & { id: ID }>{:ts}` | Create a new record |
| `update{:ts}` | `(id: ID, changes: Partial<T>) => Promise<T & { id: ID }>{:ts}` | Update an existing record |
| `delete{:ts}` | `(id: ID) => Promise<void>{:ts}` | Delete a record |

The transaction-scoped collection provides CRUD operations; it is not the full
query-builder API. Keep reads and writes inside the callback on that scoped
collection.

```ts
const result = await db.transaction(async (ctx) => {
  const orders = ctx.collection("orders")
  const order = await orders.create({ item: "book", qty: 1 })
  const found = await orders.findById(order.id)
  await orders.update(order.id, { status: "confirmed" })
  await orders.delete(order.id)
})
```

## Rollback on error

If the callback throws, all changes are discarded:

```ts
await db.transaction(async (ctx) => {
  const accounts = ctx.collection("accounts")
  const from = await accounts.findById(senderId)
  const to = await accounts.findById(recipientId)

  if (!from || from.balance < amount) {
    throw new Error("Insufficient funds") // rollback everything
  }

  await accounts.update(senderId, { balance: from.balance - amount })
  await accounts.update(recipientId, { balance: to.balance + amount })
})
```

## Returning values

Transactions return whatever the callback returns:

```ts
const ids = await db.transaction(async (ctx) => {
  const notes = ctx.collection("notes")
  const a = await notes.create({ text: "First" })
  const b = await notes.create({ text: "Second" })
  return [a.id, b.id]
})
console.log(ids) // [1, 2]
```

The IndexedDB adapter uses a native IndexedDB transaction. IndexedDB may
automatically close a transaction while the callback awaits unrelated work
(such as a network request or timer), so perform external work before or after
the transaction. The memory adapter uses an in-memory snapshot; its data is
still volatile and is lost on disconnect.

Avoid nested transactions. Keep the callback limited to its scoped database
operations so all reads and writes share the same transaction.
