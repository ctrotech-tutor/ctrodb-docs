---
title: Collection
description: Read and write records
---

A `Collection<T>{:ts}` maps to a single table or object store. All operations are async.

## Create

```ts
const record = await collection.create(data: Omit<T, "id"> & { id?: ID }): Promise<Model<T> & T>
```

- Generates a UUID (`crypto.randomUUID()` or fallback) if no `id` is provided
- Applies schema defaults
- Validates against schema
- Runs `onBeforeCreate` plugin hooks (can modify data)
- Creates record in adapter
- Runs `onAfterCreate` plugin hooks
- Emits a change event

Generated IDs are strings. You may instead provide a string or numeric ID.
Duplicate IDs and unique-index violations currently reject with a plain
`Error`, not a dedicated duplicate-record error class.

```ts
const task = await todos.create({ title: "Write docs" })
console.log(task.id, task.title)
```

## Read

```ts
const record = await collection.get(id: ID)
const all = await collection.getAll()
```

`get{:ts}` returns a single record or `undefined{:js}`. `getAll{:ts}` returns every record.

```ts
const task = await todos.get(1)
if (task) console.log(task.title)
```

`createMany(data)` creates multiple records. The built-in IndexedDB and memory
adapters perform it atomically; custom adapters without a native bulk-create
implementation use sequential creates and may leave earlier records written if
a later create fails.

## Update

```ts
const updated = await collection.update(id: ID, changes: Partial<T>)
```

- Merges changes with existing data
- Validates the merged result
- Runs `onBeforeUpdate` / `onAfterUpdate` plugin hooks
- Throws if the record does not exist
- Emits a change event

```ts
await todos.update(1, { done: true })
```

## Delete

```ts
await collection.delete(id: ID)
await collection.deleteMany(ids: ID[])
```

- Runs `onBeforeDelete` / `onAfterDelete` plugin hooks
- Emits a change event for each deleted record
- `delete` is a no-op if the record does not exist (a change event may still be emitted)
- `deleteMany` skips missing IDs

## Upsert

```ts
const record = await collection.put(data: T & { id?: ID })
```

If `data.id{:ts}` matches an existing record, updates it. Otherwise creates it.

## Count

```ts
const count = await collection.count()
```

## Query builder

```ts
const results = await collection.query()
  .where("status", "==", "active")
  .sort({ createdAt: "desc" })
  .limit(10)
  .fetch()
```

See [Query Engine](/docs/core-concepts/query-engine) for details.

## Change subscriptions

```ts
const unsub = collection.onChange((event) => {
  console.log(event.type, event.recordId)
})
```

Fires on every create, update, or delete in this collection.
Returns an unsubscribe function.

## Typing

```ts
interface Task {
  title: string
  done: boolean
}

const tasks = db.collection<Task>("todos")
const item = await tasks.create({ title: "Typed" })
// item.title is typed as string
```

Collection names are checked against the schema at runtime, but the public
string overload means they are not restricted to declared names at compile
time.
