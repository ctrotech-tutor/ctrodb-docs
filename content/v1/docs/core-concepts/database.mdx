`Database{:ts}` is the top-level object. It manages the connection, schema, collections, and plugins.

## Constructor

```ts
const db = new Database(config?: DatabaseConfig)
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `name{:ts}` | `string{:ts}` | `"ctrodb"{:txt}` | Database name |
| `adapter{:ts}` | `"indexeddb" \| "memory" \| StorageAdapter{:ts}` | auto | Storage backend |
| `schema{:ts}` | `SchemaConfig{:ts}` | — | Schema definition |
| `plugins{:ts}` | `CtroDBPlugin[]{:ts}` | — | Plugin list |
| `logLevel{:ts}` | `"debug" \| "info" \| "warn" \| "error" \| "silent"{:ts}` | — | Accepted but currently has no effect |

## Connect / Disconnect

```ts
await db.connect()
await db.disconnect()
```

`connect(){:ts}` initializes the adapter and triggers `onDatabaseInit{:ts}` on plugins.
Connect before using collections. `disconnect(){:ts}` closes the adapter and
clears collection caches. The memory adapter also loses its data on disconnect.
IndexedDB connections persist data across page reloads.

## Properties

```ts
db.isConnected   // boolean
db.adapterName   // "memory" | "indexeddb"
db.name          // string
```

## Collections

```ts
const todos = db.collection("todos")
```

Collections are cached and created lazily. With a schema, requesting an
undeclared collection throws `CollectionNotFoundError{:ts}`.

## Transactions

```ts
const result = await db.transaction(async (ctx) => {
  const todos = ctx.collection("todos")
  return todos.findAll()
})
```

If the callback throws, its writes are rolled back. Use only transaction-scoped
collections inside the callback. IndexedDB transactions can auto-close if the
callback waits on unrelated asynchronous work; keep the transaction focused on
database operations.

See the [Transactions guide](/docs/core-concepts/transactions) for details.

## Plugins

```ts
const syncPlugin = db.plugin("sync")
```

Returns the plugin instance registered with the given name, or `undefined{:js}`.

## Sync

These methods require the [sync plugin](/docs/sync/overview) to be registered.

```ts
await db.sync()
```

Triggers a full sync cycle (push local changes, pull remote changes).
Transport failures are reported through sync status and events; `sync()` does
not reject for ordinary transport errors.

```ts
const unsub = db.onSync((event) => {
  console.log(event.phase, event.progress)
})
```

Subscribes to sync lifecycle events. Returns an unsubscribe function.

```ts
db.syncStatus
// { isSyncing: boolean, isConnected: boolean, lastSyncAt: string | null,
//   pendingChanges: number, failedChanges: number, lastError: string | null }
```

Current sync status object. See [`SyncStatus`](/docs/sync/sync-engine#status) for details.

```ts
const pending = await db.getPendingCount()
const failed = await db.getFailedCount()
```

Count of pending outbound changes and failed sync attempts.

## Change events

```ts
const unsub = db.on((event) => {
  console.log(event.type, event.collection, event.recordId)
})

unsub() // cleanup
```

| Field | Type | Description |
|-------|------|-------------|
| `type{:ts}` | `"create" \| "update" \| "delete"{:ts}` | What happened |
| `collection{:ts}` | `string{:ts}` | Collection name |
| `recordId{:ts}` | `number \| string{:ts}` | Record ID |
| `record{:ts}` | `unknown{:ts}` | New value (create/update) |
| `oldRecord{:ts}` | `unknown{:ts}` | Previous value (update/delete) |

## IndexedDB connection changes

When another tab upgrades the same IndexedDB database, the existing
connection may be invalidated. Subscribe to `onConnectionChange()` to react:

```ts
const unsubscribe = db.onConnectionChange((event) => {
  if (event.type === "versionchange") {
    console.warn(event.message)
    // Reload or reconnect with a schema that includes the new version.
  }
})
```

ctrodb closes its stale connection; the database instance becomes disconnected.
Call `connect()` again with a schema at least as new as the upgraded database,
or reload the application.
