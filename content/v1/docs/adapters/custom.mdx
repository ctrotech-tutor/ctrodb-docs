---
title: Custom Adapters
description: Implementing a storage backend for ctrodb
---

Pass an object implementing `StorageAdapter` to `Database` when you need
storage beyond the built-in IndexedDB and memory adapters. The adapter handles
storage only; `Collection` remains responsible for model wrapping, schema
defaults, validation, plugin hooks, and change events.

## Adapter contract

```ts
import type {
  ID,
  ConnectionChangeEvent,
  QueryCondition,
  QueryRange,
  SchemaConfig,
  StorageAdapter,
  TransactionContext,
} from "ctrodb"

interface StorageAdapter {
  readonly name: string
  connect(name: string, schema: SchemaConfig | null): Promise<void>
  disconnect(): Promise<void>
  isConnected(): boolean
  setConnectionChangeHandler?(handler: (event: ConnectionChangeEvent) => void): void
  getSchemaVersion(): Promise<number>
  setSchemaVersion(version: number): Promise<void>

  create(collection: string, data: unknown): Promise<unknown>
  createMany?(collection: string, records: unknown[]): Promise<unknown[]>
  findById(collection: string, id: ID): Promise<unknown>
  findByIds?(collection: string, ids: ID[]): Promise<(unknown | undefined)[]>
  findAll(collection: string): Promise<unknown[]>
  count?(collection: string): Promise<number>
  hasIndex?(collection: string, indexName: string): boolean
  update(collection: string, id: ID, changes: unknown): Promise<unknown>
  delete(collection: string, id: ID): Promise<void>
  deleteMany(collection: string, ids: ID[]): Promise<void>
  scanIndex(
    collection: string,
    indexName: string,
    range: QueryRange | undefined,
    postFilters: QueryCondition[],
  ): Promise<unknown[]>
  transaction<T>(fn: (ctx: TransactionContext) => Promise<T>): Promise<T>

  getMetadata(key: string): Promise<unknown>
  setMetadata(key: string, value: unknown): Promise<void>
}
```

`createMany`, `findByIds`, `count`, and `hasIndex` are optional adapter
capabilities. If `createMany` is absent, ctrodb creates the records
sequentially; that fallback is not atomic. If `hasIndex` is absent, the query
planner treats the adapter as having no native indexes.

`QueryRange` is storage-neutral. It contains optional `lower` and `upper`
values plus `lowerOpen` and `upperOpen` flags; do not require browser
`IDBKeyRange` objects in a custom adapter.

## Transaction scope

`TransactionContext.collection(name)` returns a scoped CRUD handle. Every
operation through that handle must participate in the same transaction:

```ts
await db.transaction(async (ctx) => {
  const accounts = ctx.collection("accounts")
  const source = await accounts.findById(sourceId)
  const target = await accounts.findById(targetId)

  if (!source || !target || source.balance < amount) {
    throw new Error("Transfer cannot be completed")
  }

  await accounts.update(sourceId, { balance: source.balance - amount })
  await accounts.update(targetId, { balance: target.balance + amount })
})
```

The scoped handle provides `create`, `findById`, `findAll`, `update`, and
`delete`. It is not the regular `Collection` API and does not provide query
builders. A custom adapter's transaction implementation must roll back all
writes when the callback throws and resolve only after commit.

For browser storage, avoid awaiting unrelated work such as network calls or
timers inside the callback: native IndexedDB transactions may close while
idle. Perform that work before or after the transaction.

## Index and bulk-operation behavior

Implement `scanIndex()` using the supplied scalar range and then apply every
`where` condition in `postFilters`. `QueryCondition` may also contain
`search` or `match` predicates; do not silently treat an unsupported predicate
as satisfied. The query executor applies predicates to returned candidates,
so an indexed scan may return a superset but must not omit matching records.

If implementing `createMany()`, validate the entire batch for adapter-level
constraints before writing and commit all records atomically. The collection
layer validates schema rules before invoking the adapter.

## Register the adapter

```ts
const db = new Database({
  name: "my-app",
  adapter: new MyStorageAdapter(),
  schema: {
    version: 1,
    collections: {
      todos: {
        fields: {
          title: { type: "string", required: true },
        },
      },
    },
  },
})

await db.connect()
```

`connect()` receives the database name and schema so the adapter can prepare
its stores and indexes. Keep user data migrations explicit in the application;
the adapter contract does not define a migration callback.
