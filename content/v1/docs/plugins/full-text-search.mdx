---
title: Full-Text Search
description: Token-based search across string fields
---

The FTS plugin maintains an inverted index to accelerate tokenized `match()`
queries over searchable fields. It is optional: core search behavior works
without the plugin.

## Setup

```ts
import { Database, ftsPlugin } from "ctrodb"

const db = new Database({
  schema: {
    version: 1,
    collections: {
      articles: {
        fields: {
          title: { type: "string" },
          body: { type: "string" },
        },
        searchable: ["title", "body"],
      },
    },
  },
  plugins: [ftsPlugin()],
})
```

## How it works

The plugin stores postings in the internal `_ctrodb_fts{:ts}` store. Each
posting represents one collection-token-document association; the store's
record layout is an implementation detail.

**Indexing:**
- On create/update/delete, postings are added, changed, or removed for tokens
  extracted from searchable fields
- Tokens are stored as per-document postings rather than a shared array of
  document IDs, so concurrent writes do not overwrite one another
- Tokens are lowercased, deduplicated, and filtered for stop words

## Substring search

`.search(){:ts}` is a case-insensitive substring scan, with or without the FTS
plugin. It does not use the inverted index:

```ts
const results = await articles
  .query()
  .search("body", "database schema")
  .fetch()
```

This checks whether the `body` field contains the literal text
"database schema".

## Tokenized matching

Use the query builder's `match()` method to search all schema `searchable`
fields by default, or pass field names explicitly:

```ts
const results = await articles
  .query()
  .match("database schema", ["title", "body"])
  .fetch()
```

Matching tokenizes the input, removes common stop words, and requires all
remaining whole-word terms to match. The plugin accelerates this query; it is
not required for the same matching semantics.

## Indexed search (FTSIndexer)

To use the inverted index directly:

```ts
import { FTSIndexer } from "ctrodb"

const indexer = new FTSIndexer(adapter)
const ids = await indexer.search("articles", "database schema")
// ids contains IDs of documents matching ALL tokens (AND logic)
```

`FTSIndexer.search(){:ts}` tokenizes the query and returns document IDs
containing every non-stop-word token.

## Built-in stop words

Common English words are excluded: a, an, and, are, as, at, be, but, by,
for, if, in, into, is, it, no, not, of, on, or, such, that, the, their,
then, there, these, they, this, to, was, will, with.

## Tokenizer

```ts
import { tokenize } from "ctrodb"

tokenize("Hello World!") // ["hello", "world"]
```

The tokenizer splits on non-alphanumeric characters and lowercases.
Duplicates are removed. Stop words are filtered.
