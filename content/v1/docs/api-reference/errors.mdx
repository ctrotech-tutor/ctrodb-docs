---
title: Errors
description: Error classes
---

Database errors extend `CtrodbError{:ts}`, which extends `Error{:js}`.
`SyncResponseValidationError` is a separate `Error` subclass.

```ts
import {
  CtrodbError,
  ConnectionError,
  CollectionNotFoundError,
  RecordNotFoundError,
  SchemaError,
  ValidationError,
  QueryError,
  StorageQuotaError,
  SyncResponseValidationError,
} from "ctrodb"
```

## CtrodbError

Base error class. Sets `this.name = "CtrodbError"{:js}`.

## ConnectionError

Thrown when operations are attempted before connecting.

```ts
new ConnectionError(dbName, reason?)
// "Failed to connect to database "foo": reason"
// or "Database "foo" is not connected. Call db.connect()..."
```

## SchemaError

Thrown when schema configuration is invalid.

```ts
new SchemaError(message)
// Invalid schema configuration.
```

## ValidationError

Thrown when a record violates field validation rules.

```ts
new ValidationError(collection, field, message, value?)
// 'Field "email" in collection "users": is required.'
```

Has `.field{:ts}`, `.collection{:ts}`, `.value{:ts}` properties.

## CollectionNotFoundError

Thrown when a schema-constrained database is asked for an undeclared
collection.

## RecordNotFoundError

Thrown by `Collection.update()` when the requested record does not exist.
`Collection.delete()` is a no-op for a missing ID.

## StorageQuotaError

Represents a storage quota failure.

## SyncResponseValidationError

Thrown when a remote sync response does not match the expected push or pull
response shape.

## QueryError

Exported for query-related errors, but not used for ordinary built-in query
failures.

## Duplicate IDs

Duplicate IDs and unique-index violations currently reject with a plain
`Error`; there is no dedicated duplicate-record error class.
