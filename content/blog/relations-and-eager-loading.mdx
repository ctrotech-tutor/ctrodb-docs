Real applications have relational data: users have posts, posts have comments, orders have items. ctrodb supports three relationship types — `has_many`, `belongs_to`, and `has_one` — with both lazy accessors and eager loading.

## Defining Relations

Relationships are defined in the `relations` field of a collection schema:

```typescript
import { createDatabase, defineSchema } from "ctrodb"

const schema = defineSchema({
  version: 1,
  collections: {
    users: {
      fields: {
        name: { type: "string", required: true },
        email: { type: "string" },
      },
      relations: {
        posts: {
          type: "has_many",
          collection: "posts",
          foreignKey: "userId",
        },
      },
    },
    posts: {
      fields: {
        title: { type: "string", required: true },
        body: { type: "string" },
        userId: { type: "string", required: true },
        createdAt: { type: "number" },
      },
      relations: {
        author: {
          type: "belongs_to",
          collection: "users",
          foreignKey: "userId",
        },
        comments: {
          type: "has_many",
          collection: "comments",
          foreignKey: "postId",
        },
      },
    },
    comments: {
      fields: {
        text: { type: "string", required: true },
        postId: { type: "string", required: true },
        createdAt: { type: "number", required: true },
      },
    },
  },
})
```

### Relation Types

- **`has_many`** — The source record has many related records. Example: a user has many posts. The getter returns a QueryBuilder configured to find all records in the target collection where `foreignKey` matches the source record's ID. When eager loaded, the related records are grouped and assigned as an array.

- **`belongs_to`** — The source record belongs to one related record. Example: a post belongs to an author (user). The getter returns a QueryBuilder configured to find the record where `id` matches the source's `foreignKey` value. When eager loaded, the related record is fetched and assigned as a single object.

- **`has_one`** — The source record has exactly one related record. Example: a user has one profile. Similar to `has_many` but returns a single object instead of an array when eager loaded.

## Lazy Relations (Built-in)

Lazy relation accessors are built into the `Model` class — no plugin needed. When you have a model instance, you can access relations as properties:

```typescript
const users = db.collection("users")

// Fetch a user
const user = await users.get("user-id")

// get() may return undefined when the ID is missing
if (user) {
  // The relation property is a QueryBuilder; fetch() runs it
  const posts = await user.posts.fetch()
}
```

Each relation property returns a `QueryBuilder` pre-configured to fetch the related records. Then you call `.fetch()` to execute the query.

### How Lazy Relations Work

When a collection schema defines relations, the `Model` constructor uses `Object.defineProperty` to attach getter properties:

- **`has_many` / `has_one`**: Creates a query: `target_collection.query().where(foreignKey, "==", this.id)`
- **`belongs_to`**: Creates a query: `target_collection.query().where("id", "==", this[foreignKey])`

The query is re-executed each time you call `.fetch()`, ensuring you always get the latest data.

## Eager Loading

Lazy relations run a query each time they are accessed. For lists, eager loading
through `Collection.with()` batches relation loading rather than querying once
per model. Relation access and eager loading are built into the core; the
relations plugin is not required.

### Setup

Create the database with the schema; no relation plugin is needed:

```typescript
const db = createDatabase({
  name: "blog",
  adapter: "memory",
  schema,
})

await db.connect()
```

### Using `.with()`

When the collection schema declares relations, `.with()` can eagerly load them:

```js
const posts = db.collection("posts")
const postsWithAuthors = await posts.with("author").fetch()
const firstPost = postsWithAuthors[0]
console.log(firstPost?.author?.name) // Loaded at runtime, if the author exists

const fullPosts = await posts
  .with("author", "comments")
  .fetch()
```

These are runtime shapes. TypeScript currently types relation properties on
`with()` results as lazy `QueryBuilder` accessors, not as eager values.
With a schema created by `defineSchema()` and a database created by
`createDatabase()`, use `Model.load()` when you need a correctly typed
related value.

### How Eager Loading Works

When you call `.with("author", "comments")`:

1. The main query fetches all posts (or applies your `where`/`sort`/etc.)
2. Related collections are read and matched to the requested relation fields.

This reduces per-record query overhead, but eager loading currently reads the
full related collection for each requested relation. It is not a targeted
indexed join and may be expensive for large related collections.

## Practical Example: Blog Dashboard

```javascript
async function loadDashboard() {
  const posts = db.collection("posts")

  // Eager load everything
  const postsWithData = await posts
    .with("author", "comments")
    .sort({ createdAt: "desc" })
    .limit(20)
    .fetch()

  return postsWithData.map((post) => ({
    title: post.title,
    author: post.author?.name,
    commentCount: post.comments?.length ?? 0,
    lastComment: post.comments
      .sort((a, b) => b.createdAt - a.createdAt)[0]?.text,
  }))
}
```

## Loading Related Data of Related Data

Eager loading is one level deep. For deeper nesting, you can lazy-load relation data after the initial fetch:

```typescript
const users = await db.collection("users").with("posts").fetch()
const firstUser = users[0]
const firstUserPosts = firstUser ? await firstUser.load("posts") : []
const firstPost = firstUserPosts[0]
const comments = firstPost
  ? await firstPost.load("comments")
  : []
```

## Empty and Missing Relations

ctrodb handles edge cases gracefully:

```typescript
const usersCollection = db.collection("users")
const postsCollection = db.collection("posts")

// User with no posts → posts is an empty array
const newUser = await usersCollection.create({ name: "New User" })
const userPosts = await newUser.posts.fetch()
console.log(userPosts.length) // 0

// Post with missing author → the relation query has no result
await postsCollection.create({
  title: "Orphan",
  body: "...",
  userId: "missing-user",
})
const orphan = await postsCollection.query().where("title", "Orphan").first()
const author = orphan ? await orphan.author.first() : undefined
console.log(author) // undefined
```

## Performance Considerations

| Approach | Queries | Best For |
|---|---|---|
| Lazy access | 1 + N queries | Single-record views, detail pages |
| Eager loading (.with()) | Main query plus a full read of each related collection | Lists with moderate related collections |

Use eager loading to avoid one relation query per model, but account for the
full related-collection reads it currently performs.

## Schema-less Relations

Without a schema, you can still define relations programmatically by creating your own helper methods. However, the lazy getters and `.with()` API require a schema with `relations` defined.

## Summary

ctrodb's relations system provides:

- Three relation types: `has_many`, `belongs_to`, `has_one`
- Lazy accessors built into every Model (plugin-free)
- Eager loading via `.with()` without a required plugin
- Batched relation loading, with full related-collection reads
- Automatic relation getter generation from schema

Whether you're building a blog, an e-commerce catalog, or a social feed, schema
relations keep your data model expressive. Benchmark eager loads with realistic
collection sizes because they currently read each related collection in full.
