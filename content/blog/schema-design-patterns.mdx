A good schema makes your app easier to build and maintain. Here are patterns that work well with ctrodb.

## 1. Flat collections over nested documents

ctrodb does not support nested document schemas. Each collection is a flat table. This is intentional — flat structures are easier to query, index, and maintain.

Instead of this:

```ts
{
  users: {
    fields: {
      name: { type: "string" },
      posts: { type: "array", items: { ... } }
    }
  }
}
```

Do this:

```ts
{
  users: {
    fields: { name: { type: "string" } }
  },
  posts: {
    fields: {
      title: { type: "string" },
      userId: { type: "string" },
    },
    indexes: [{ field: "userId" }]
  }
}
```

Declare relations in the schema to connect them. Lazy relation access and
`Collection.with()` eager loading are built in; `relationsPlugin()` is optional
and not required for these APIs.

## 2. Defaults for temporal fields

Timestamps are common enough that defaults should be automatic:

```ts
createdAt: { type: "number", default: () => Date.now() }
updatedAt: { type: "number", default: () => Date.now() }
```

There is no automatic update on mutation — set `updatedAt` in your update calls
or implement that behavior in a plugin.

## 3. Enums via validation

ctrodb does not have a native enum type. Use `validate` with a regex or function:

```ts
status: {
  type: "string",
  validate: (v) => ["active", "archived", "deleted"].includes(v as string)
}
```

Or use the validation plugin for more complex rules.

## 4. Unique fields via indexes

Set `unique: true` on an index to prevent duplicate values:

```ts
indexes: [
  { field: "email", unique: true }
]
```

The configured adapter enforces the unique constraint. Duplicate-ID and
unique-index failures currently reject with a plain `Error`.

## 5. Searchable fields

Mark string fields as `searchable` when you need tokenized `match()` queries:

```ts
searchable: ["title", "description"]
```

Only string fields should be marked searchable. `match()` works without a
plugin; `ftsPlugin()` maintains an index to accelerate matching. A regular
field index does not accelerate substring `search()`.

## 6. Version your schema

The `version` field in `SchemaConfig` controls IndexedDB object-store and index
upgrades:

```ts
{
  version: 2,
  collections: { ... }
}
```

Increment it when the IndexedDB stores or indexes need an upgrade. ctrodb does
not provide a user data-migration callback or automatically delete removed
stores. Backfill or transform existing records with an application migration.

## 7. Keep it small

A client-side database works best with focused collections. A schema with 5-10 collections is easier to manage than one with 50. Split large schemas into separate database instances if needed.
