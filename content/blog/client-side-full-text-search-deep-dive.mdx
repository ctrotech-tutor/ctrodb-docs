Full-text search is one of the most requested features for client-side applications. ctrodb's FTS plugin provides an inverted index engine that runs entirely in the browser — no server, no external API, no network requests.

## How It Works

The FTS plugin builds an inverted index from searchable fields. It stores a
posting for each collection, token, and document ID. A tokenized query looks up
each token's postings and intersects the document IDs to find records that
contain every term.

```
Token: "typescript" → Documents: [1, 3, 7, 12]
Token: "react"      → Documents: [1, 5, 7]
Token: "hooks"      → Documents: [7, 12]

Search "react hooks" → [7]
```

## Setting Up the FTS Plugin

Import and add the plugin to your database configuration:

```typescript
import { Database } from "ctrodb"
import { ftsPlugin } from "ctrodb"

const schema = {
  version: 1,
  collections: {
    articles: {
      fields: {
        title: { type: "string", required: true },
        body: { type: "string", required: true },
        published: { type: "boolean" },
        createdAt: { type: "string" },
      },
      searchable: ["title", "body"],
    },
  },
}

const db = new Database({
  name: "blog",
  adapter: "indexeddb",
  schema,
  plugins: [ftsPlugin()],
})

await db.connect()
```

The `searchable` field tells the plugin which fields to index.

## Searching

Use `match()` for tokenized, whole-word matching:

```typescript
const articles = db.collection("articles")

const results = await articles
  .query()
  .match("react hooks", ["title", "body"])
  .where("published", true)
  .sort({ createdAt: "desc" })
  .limit(10)
  .fetch()
```

`match()` requires every non-stop-word token to match. It works without the
plugin by scanning records; `ftsPlugin()` accelerates it when the index is
available. In contrast, `.search("title", "react")` is a case-insensitive
substring scan and does not use the FTS index.

## Tokenization

The tokenizer converts text into searchable tokens:

```typescript
import { tokenize } from "ctrodb"

const tokens = tokenize("React Hooks: A Comprehensive Guide")
// ["react", "hooks", "comprehensive", "guide"]
```

It converts to lowercase, splits on non-alphanumeric characters, removes
duplicates, and filters common English stop words.

## Performance

Search cost depends on query token count and the matching posting sets; avoid
assuming a fixed latency. The internal `_ctrodb_fts` store contains posting
records, and its layout is an implementation detail.

## When to Use FTS vs. Basic Search

- **Substring search** (`query().search()`) — Case-insensitive substring scan of one field.
- **Tokenized matching** (`query().match()`) — Whole-word AND matching across searchable fields; the FTS plugin can accelerate it.

## Summary

The FTS plugin provides tokenized whole-word matching locally, with no external
search service, API key, or network request.

### Key Points

- Automatic posting maintenance via plugin hooks on create/update/delete
- Tokenized whole-word matching with stop-word removal
- Multi-field search with the query builder
- Search cost depends on the query and matching postings; benchmark with your data
- Works with both memory and IndexedDB adapters
